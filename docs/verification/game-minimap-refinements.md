## 已核对的事实与后续建议

- 当前圆屏仅接收二维材质像素，无楼高/3D网格。iOS建筑输入来自同视角开关楼块差分，cameraDegree为0.05度，接近正俯视；4m掩码投回2m道路栅格。把SDK楼块关闭会失去这条建筑提取来源，不会自动得到更便宜的平面轮廓。
- 粗糙来源有4m建筑量化、硬阈值分类、道路加粗和圆屏普通栅格最近邻旋转采样。道路已有3x3清理，不能把再模糊一遍当作无风险优化。
- 建议先在iOS每个新块仅进行一次保结构去噪/轮廓简化；保留窄路、水域、孔洞和相邻块接缝，复用缓存。边缘抗锯齿单独测量，不启用全屏超采样，也不承诺计算与传输必然同时下降。
- 用户确认立交问题指底图。当前分类仅地面/道路/绿地/水域，随后一像素膨胀会填掉窄分隔。先验证保留桥梁边线和限制跨缝加粗；从已压平的道路掩码不能还原真实上下层。需要输入提供层级时才做可靠分层配色，不猜测高低关系。
- 新的二维轮廓简化/道路平滑/立交分层尚未修改生产算法；先以同区域生产预览确认观感与路网保持，再实施。
