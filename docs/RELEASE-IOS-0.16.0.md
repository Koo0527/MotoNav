## Build14 定位修复

修复驾车模拟定位写入导航缓存后，结束模拟仍被当作当前位置的问题。自然结束、手动退出及新导航初始化会清理旧坐标；“当前位置”和昼夜设置仅采用真实导航/巡航定位或手机定位，模拟进度继续用于模拟导航画面。结束后的迟到回调保持隔离；没有手机定位时返回未定位，不再使用模拟目的地。

已通过回归测试、独立代码复核和arm64签名编译。回归测试执行真实的导航定位回调、结束/重置方法及坐标转换，覆盖自然结束、手动退出、位置移动、迟到模拟回调、下一次GPS导航和无真实定位情形。独立路线模拟坐标仅用于其导航画面，没有写入手机定位服务。

## Build15 骑行引擎升级与统一UI

普通自行车导航默认升级到高德官方 `AMapNaviRideManager` 引擎：由SDK承担定位匹配、转向引导、偏航重算和到达判断；官方引擎失败时明确提示，可选择兼容引擎重新规划，不静默切换。自行车分享默认保留原轨迹独立导航，规划页另提供“用官方引擎重新规划”。

新增 `NavigationCoordinator` 统一管理驾车与骑行SDK实例：按固定顺序失效回调、停止导航、解绑地图后销毁旧实例再创建新引擎，销毁失败不重复创建；移除启动时无条件创建驾车引擎的行为。规划后端标识扩展为 `driveSDK / rideSDK / independent`，出行方式与实际引擎分别记录。`RideBridge` 提供骑行规划、选路、真实/模拟导航与暂停继续，回调转换为现有导航读数与BLE圆屏消息（转向、距离、道路、速度、剩余、ETA、GPS状态、到达），不改ESP32协议；SDK匹配位置用于导航，手机定位继续用于当前位置与轨迹，真实导航记录轨迹、模拟不记录。

三种导航界面收敛为地图优先统一布局：顶部紧凑卡片（方向、下次动作与距离、道路、ETA、剩余），底部玻璃控制栏（速度、全览/跟随、静音、隧道、更多），驾车用Drive地图、官方骑行用Ride地图、网页/分享兼容沿用现有地图。官方骑行地图在夜间配色时保持日间样式（SDK 限制），HUD 深色背板保证信息可读。已通过16套回归测试（含ride-bridge、ride-ble-parity、ride-units、unified-navi-ui等）与arm64签名Release编译；真机骑行引擎回调、圆屏联测与实车场景待用户验收（见[验证记录](VERIFY-RIDE-ENGINE-BUILD15.md)）。

## 车道发送顺序修复（源码，待圆屏复测）

修复蓝牙暂时没有发送额度时的清屏竞态：新车道可能复用旧车道在队列中的位置，先于清屏发送而被擦掉；新的转向也可能覆盖尚未发送的清屏。现在清屏单独排队，并移除上一会话待发的导航状态和文字图片，再发送新车道与转向。硬件参数及媒体控制指令保留，蓝牙协议不变。

回归覆盖发送阻塞、清屏与车道/转向顺序、重连缓存、车道隐藏后恢复和到达清理。此修复未改变固件的车道显示条件：175地图及箭头页仍跟随500米内的转弯倒计时，185b地图页仍限定150米内的非直行提示。App有车道而圆屏不显示时，还需结合方向、距离和实测固件区分显示限制与同步问题。

## iPhone与圆屏实测

1. 先模拟一条起点远离实际位置的路线；自然结束或手动退出后，再选择“我的位置”作为起点，确认回到真实位置，移动手机后仍可更新。
2. 用首页搜索选一个目的地，切换三种出行方式；确认起终点、途经点保留，预览和开始导航在同一页面。自行车不支持的输入应给出提示。
3. 分别从收藏、最近目的地和高德分享进入，确认同一规划流程。摩托车分享仍使用驾车策略。
4. 模拟驾车导航，切换App导航和完整高德提示，检查导航持续、全览边距、静音/模拟速度与退出行为。
5. 连接圆屏，白天先手动点“隧道”，确认降低到夜间亮度上限；再点恢复，检查原有偏好不变。隧道中断连重连，确认同步当前有效亮度。
6. 在安全停靠或由乘客观察的条件下，验证真实隧道入口、隧道内定位丢失、出口恢复和相邻隧道；实际识别效果取决于SDK道路类型和匹配定位。
7. 逐个切换恢复的风格，检查旧地图被替换，重新打开App仍保留选择；卫星图数据较大，龙珠雷达无需底图。
8. iOS红绿灯读秒暂缓，不再作为本轮测试或交付要求；红绿灯位置、距离和灯数与读秒分别处理。

只验证iOS；上游Android和固件更新原样合入，未编译或烧录。地图传输和12种主题的最终显示仍需对应圆屏固件实测。

### Build23：后台省电（心跳降频 + 空闲断开）

- 修复后台持续耗电：此前 App 因蓝牙常连在后台从不休眠，2 秒心跳（"P"、时钟同步）全天运行。
- 方案 A（自动）：锁屏且链路空闲时心跳从 2 秒放慢到 25 秒；前台或忙碌（导航／巡航／G 录制／圆屏音乐模式／地图数据未传完）保持 2 秒，导航中 "P" 照旧，圆屏“数据中断”提示行为不变。
- 方案 B（默认开，圆屏设置里“锁屏空闲省电”开关可关）：锁屏且链路空闲持续满 3 分钟（固定值）断开圆屏连接，App 随即可被系统挂起；回到 App 数秒内自动重连（直连不走扫描）。圆屏不在身边时同样生效（停掉后台扫描重试循环）。空闲计时从链路最后一次确认忙碌起算，锁屏骑行到站后重新计时。
- 新增纯逻辑类型 BleIdlePolicy 与回归测试 ios/tests/ble-idle-policy（281 项断言，已登记 CI）；固件无改动。
- 真机验收清单：
  1. 连接圆屏 → 立即锁屏放置约 3.5 分钟 → 圆屏显示断开、回 App 显示“锁屏空闲省电已断开，回到 App 自动重连”，电池页后台活动不再增长；
  2. 回前台数秒内自动重连；
  3. 驾车／骑行导航中锁屏 10 分钟不断开、导航与播报正常；
  4. 巡航中锁屏不断开；音乐 HID 模式锁屏放歌不断开；
  5. 关闭“锁屏空闲省电”开关 → 恢复只降频不断开；
  6. （可选）一晚 A/B 对比电池页后台用量，量化收益。
