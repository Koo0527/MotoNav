# iOS 统一路线流程与隧道调光

用户已同意统一搜索、方式选择、路线预览、导航流程，并加入隧道调光。直接在当前工作区实现，保留已有修改。

- 仅修改 iOS、对应测试及文档；不改 Android 和 ESP32 固件，不新增依赖。
- 首页选择目的地后进入同一个规划页面，在驾车、摩托车、自行车之间切换。常用地点、历史和分享入口均进入此流程。
- 驾车继续使用现有 SDK 引擎，摩托车分享继续使用驾车策略；网页摩托车及自行车保持现有已可用的算路与跟随能力，不擅自切换未验证权限的服务。
- 同一规划页保留起终点、途经点、路线选择、真实/模拟导航；不支持的输入明确说明，切换模式不得静默丢失途经点。旧规划响应不能覆盖当前模式或目的地。
- 三种导航继续使用已统一的 App 显示层，高德完整导航提示入口保留。返回设置后导航继续运行，结束与到达恢复主页。
- 驾车导航通过新鲜、有效且匹配当前路径的 SDK 位置、路段类型识别隧道，并在距入口 80 米内提前调暗；不能以 GPS 丢失或名称猜测为依据。
- 驾车以外当前缺少可靠隧道类型，明确自动能力范围；所有模式提供临时隧道模式快捷操作。
- 隧道目标亮度取用户正常亮度与夜间亮度的较低值，范围 5–255；切换深色配色，出洞恢复原偏好，不改写持久亮度和配色。自动识别默认开启并可关闭。
- 接近入口需持续确认 0.8 秒；已在隧道的有效证据立即调暗。出洞需连续确认 3 秒，未知证据不升亮；超过 2.5 秒的观测间隔和时间倒退取消待确认转换。
- 每 0.1 秒最多调节 32 级；蓝牙重连强制发送当前有效亮度。导航结束清理临时状态和计时器，旧会话回调不能调光。
- 单元验证覆盖无效索引、非有限距离、短隧道、相邻隧道、定位中断、出洞抖动、偏好恢复和渐变范围。真机签名构建、安装启动与道路验证分开报告。
