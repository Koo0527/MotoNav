# MotoNav iOS 0.15.1

本轮仅修改 iOS 客户端及其测试、构建发布流程。摩托车分享后使用驾车算路是为适应禁摩规划的既定策略，本轮保留。Android 与 ESP32 固件源码没有改动。

- 搜索：每次主动搜索按当前定位请求结果；取消搜索或发起新搜索后，旧请求的成功及失败回调不会覆盖当前页面。
- 自行车：算路时显式请求分段坐标、转向指令和耗时，修复请求遗漏扩展字段导致的“自行车路线缺少分段”。
- 导航界面：首页搜索导航、自行车及摩托车独立路线共用 App 风格的信息卡片、全览、静音、模拟控制和长按结束操作。驾车导航提供“完整导航提示”，可在当前导航中切回高德原生界面；地图代表对象保持连接，算路和导航引擎不变。全览按实际卡片高度预留地图空间。
- 轨迹：后台串行追加每个有效 WGS84 定位点，结束时保存完整 JSON。兼容旧记录、历史列表和 GPX；意外退出后从完整日志行恢复，忽略未写完的末行。
- 时间：圆屏认证连接后发送当前时间与时区，每分钟校准；时间跳变、时区变化和重新连接时重新同步。时间包不作为旧状态重放，旧固件可忽略不认识的命令。
- 构建：iOS 主应用、分享扩展及发布版本统一为 0.15.1；iOS 发布流程独立构建 iOS，不再附带构建或发布 ESP32 固件。

电脑端回归测试：`python3 ios/tests/ios-fixes/check.py`；路线回归：`python3 ios/tests/webmotor/check.py`；校时测试：`swiftc ios/MotoNav/PhoneClockSync.swift ios/tests/phone-clock/main.swift -o /tmp/motonav-clock && /tmp/motonav-clock`。本地完整构建入口为 `bash scripts/build-ios-local.sh`，生成未签名 IPA，需使用本人的 Apple 账号签名安装。

构建号 3 已通过 iPhone arm64 Release 编译、新增三组回归和原有逻辑回归，并校验主应用及分享扩展版本、IPA 内容和 SHA256。包含自行车修复、统一导航界面及读秒诊断的临时构建号 6 已通过路线、界面切换和到达回归、iPhone arm64 Debug 编译和签名校验，并安装、启动于 iPhone 15 Pro。自行车规划已由用户确认恢复；统一界面及原生高级提示的道路效果仍待真机验证。保留本地已有的工程配置，最低要求 iOS 17.0。

iPhone 验证时请检查：

1. 在两个不同地点主动搜索相同关键词，确认结果更新；快速切换关键词、清空搜索框，确认旧结果不会重新出现。
2. 开始真实导航或巡航，结束后查看轨迹并导出 GPX；退出并重新打开应用，确认旧记录仍可读。模拟导航仍不记录轨迹。
3. 使用支持主页时钟的圆屏固件，设备重启后连接 iPhone，检查时间、日期和断连后的继续走时；重连后应重新校准。
4. 验证导航、锁屏、语音、BLE 和地图的长时间配合。电脑端编译与合成回归不能代替这些真机检查。
5. 重新规划此前报错的自行车路线，检查地图、距离、耗时及导航转向指令。
6. 对比首页搜索、自行车和摩托车规划的导航界面；在驾车导航中切换“完整导航提示”和“返回 App 风格”，检查同一次导航持续运行、全览边距及原生高级提示。

ESP32 断连后原分享路线叠加层无法恢复的问题仍保留在审查报告中，本轮没有修改固件解决该问题。iOS 仍不包含红绿灯读秒。
